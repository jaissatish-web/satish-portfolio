2oo3 voting and cause-and-effect testing

Separate a Boolean voting example from a complete safety-function verification.

By Satish Kumar Jaiswal · 2026-09-23

2oo3 Voting SimulatorCause & Effect Tests

In a simplified two-out-of-three vote, any two input demands produce the output demand. One input alone does not. The interactive simulator shows the three input states and the resulting vote, making the Boolean relationship easy to inspect.

Try the combinations

Select demand on sensor 1 only: no trip. Add sensor 2: trip. Return sensor 1 to normal: no trip. Add sensor 3 while sensor 2 still demands: trip. The identity of the pair does not change the basic rule.

A vote is only one part of the function

Real systems may include input diagnostics, discrepancy handling, bypasses, timing, latching and reset conditions. The simple model does not represent these behaviors, nor does it calculate SIL or probability of failure. Do not infer the complete safety function from a three-input truth table.

Make the test record specific

For each cause-and-effect pair, identify the approved matrix revision, initiating tag, expected output tag, alarm, timing and reset conditions. Use a separate record ID in the checklist so results from different pairs do not overwrite each other on the same device.

Record observation, not just a tick

The checklist distinguishes pending, pass, fail and not applicable. Enter actual response and timing in the notes field. A reviewed item can still be failed; the progress chart deliberately keeps those counts separate. Export the record and retain it with the approved evidence.

Test under an authorized procedure

Testing can affect connected equipment. Simulation method, operating state, bypass authorization, communication and restoration must be defined by the approved procedure. This website is a learning and record aid, not authorization to force I/O or defeat a protective function.
